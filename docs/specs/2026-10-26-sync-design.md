# Ireadbook — ซิงก์ระหว่างเครื่อง (ทาง A: ตรงระหว่างเครื่อง)

วันที่: 2026-10-26 · ผู้ใช้เลือก: ซิงก์ตรงระหว่างเครื่อง, เปิดให้คนทั่วไปใช้, โฮสต์บน GitHub Pages

## เป้าหมาย
ใช้ได้ทั้งคอมและมือถือ ข้อมูลเป็นชุดเดียวกัน โดยไม่มีระบบสมัครและไม่มีเซิร์ฟเวอร์ของเราเอง

## พฤติกรรม
- เปิดครั้งแรก: สร้างชั้นหนังสือ (libraryId + libraryKey สุ่ม) และรหัสเครื่อง (deviceId) อัตโนมัติ
- จับคู่: เครื่อง A กด "เชื่อมเครื่องใหม่" → รหัส 6 ตัว (ตัวอักษรที่อ่านง่าย ไม่มี 0/O/1/I) ใช้ได้ 5 นาที
  เครื่อง B กรอกรหัส → B เข้าร่วมชั้นของ A (ใช้ libraryId/libraryKey ของ A) → ซิงก์เต็มทันที (ข้อมูลเดิมของ B ถูกรวมเข้าไป ไม่หาย)
- หลังจับคู่: เปิดแอปเมื่อไร จะหาและเชื่อมกับเครื่องที่จับคู่ไว้เอง ซิงก์เมื่อเจอ และส่งการแก้ไขสดๆ ระหว่างที่เชื่อมอยู่
- ปุ่ม "ซิงก์ตอนนี้", สถานะต่อเครื่อง, เวลาที่ซิงก์ล่าสุด, ยกเลิกการเชื่อมเครื่อง
- หน้าเริ่มต้น: "มีชั้นหนังสืออยู่ในเครื่องอื่น? กรอกรหัส"

## การรวมข้อมูล
- ทุกระเบียนมี updatedAt: ฉบับที่ใหม่กว่าชนะ
- การลบเก็บเป็น tombstone {table, id, deletedAt}; ระเบียนที่ updatedAt ≤ deletedAt ถูกลบ
- รูปภาพไม่เปลี่ยนหลังสร้าง: ส่งเฉพาะรูปที่อีกฝั่งยังไม่มี
- อชีฟเมนต์: รวมกัน ใช้ unlockedAt ที่เก่าที่สุด
- ตั้งค่าที่ซิงก์: เป้ารายวัน/ปี, Pomodoro, ห้องและการปรับแต่งห้อง (ใหม่กว่าชนะ); ไม่ซิงก์: คุณภาพกราฟิก เสียง มุมมอง วันที่สำรองล่าสุด

## การส่งข้อมูล
- WebRTC ผ่าน PeerJS (ใช้เซิร์ฟเวอร์หาเครื่องฟรีของ PeerJS เพื่อเริ่มการเชื่อมเท่านั้น ข้อมูลวิ่งตรงและเข้ารหัสโดย WebRTC)
- peer id ของเครื่อง: `ireadbook-<deviceId>` (สุ่ม 128 บิต), peer id ช่วงจับคู่: `ireadbook-pair-<code>`
- เชื่อมแล้วต้องยืนยัน libraryKey ก่อนแลกข้อมูล ไม่ตรงตัดทันที
- โปรโตคอล: hello → manifest (id+updatedAt ต่อระเบียน, tombstones, รายการรูป) → request → data/image → done
- ชั้น transport แยกออกมา ทดสอบด้วย BroadcastChannel (จำลองสองเครื่องในเบราว์เซอร์เดียว)

## ข้อจำกัด
- ซิงก์เฉพาะตอนเปิดทั้งสองเครื่อง
- ไม่มี TURN server: บางเครือข่าย (เช่น เน็ตมือถือกับ Wi-Fi บ้าน) อาจเชื่อมไม่ติด แนะนำ Wi-Fi เดียวกัน; ไฟล์สำรองยังใช้ได้เสมอ
- ขึ้นกับบริการฟรีของ PeerJS

## ทดสอบ
- unit: manifest/plan/apply (tombstone, ใหม่กว่าชนะ, รูป, อชีฟเมนต์, ตั้งค่า), รหัสจับคู่หมดอายุ
- e2e: สองแท็บ (BroadcastChannel) จับคู่ด้วยรหัส → ข้อมูลรวมกัน → แก้ในแท็บหนึ่ง อีกแท็บเห็น → ลบแล้วหายทั้งสองฝั่ง
